# 프라이버시 설계

프라이버시는 이 서비스의 부가 요소가 아니라 **럭셔리 브랜드 신뢰의 구성 요소**다.
AI 가 구매 여정에 개입할수록 신뢰가 장인정신만큼 중요해진다는 것이 이 서비스의
시장 전제이기도 하다 (PRD §2.4).

다만 **과장하면 역효과**다. 현재 할 수 있는 것과 실서비스에서 할 것을 구분해 서술한다.

---

## 1. 서비스가 다루는 이미지는 한 종류뿐이다

**분석용 스틸컷.** 그 외에 서비스가 만들거나 보관하는 이미지는 없다.

| | 분석용 이미지 |
|---|---|
| 목적 | LLM 착장 분석 |
| 개시 주체 | 시스템 (동의 후 자동) |
| 저장 | **하지 않음** — RAM 내 처리 후 폐기 |
| 직원 전달 | **하지 않음** — 분석 결과 텍스트만 |
| 동의 | 시작 화면의 명시적 동의 |

고객이 자기 휴대전화로 찍는 사진은 **처음부터 고객의 것이고 서비스는 관여하지 않는다.**
서버는 촬영이 일어났는지조차 알지 못한다 ([EXPERIENCE_SPEC §3](EXPERIENCE_SPEC.md)).

> 서비스가 사진을 만들어 전달하는 설계였다면 "분석용 이미지는 안 남기지만 촬영 사진은
> 잠깐 남깁니다"라는 예외를 설명해야 했다. 파이프라인이 하나뿐이므로 그런 예외가 없다.
> **설명할 예외가 없다는 것이 이 설계의 이점이다.**

---

## 2. 처리 단계 로드맵

**현재 외부 Vision API 를 사용한다. 이 사실을 감추지 않는다.** 외부 API 를 호출하면서
"폐쇄망"이라고 주장하면, 아는 심사위원 한 명만 있어도 신뢰가 통째로 무너진다.

| 단계 | 처리 방식 | 보장 수준 |
|---|---|---|
| **시제품 (현재)** | 외부 Vision API 호출 + 인메모리 처리 + 즉시 폐기 | 자체 저장 없음 |
| **파일럿** | 외부 API + **학습 미사용·무보존 계약 조건** 적용 | 저장 없음 + 학습 없음 |
| **운영 확장** | **사내 서버 온프렘 VLM**(Qwen-VL·InternVL 급) 또는 프라이빗 네트워크 기반 내부망 AI | **이미지가 매장 밖으로 나가지 않음** |

> 발표 논지: "지금은 외부 API 를 씁니다. 실서비스에서는 사내 서버에서 오픈소스 VLM 을
> 폐쇄망으로 돌립니다. 이 수준의 착장 분석에는 온프렘 모델로 충분합니다."
> — 정직하면서 동시에 기술 로드맵이 있다는 신호가 된다.

---

## 3. "저장하지 않는다"를 지키기 위한 구현 제약

말보다 지키기가 어렵다. 사고가 나는 지점은 정해져 있으므로 구현 제약으로 못박는다.

- **multipart 대신 JSON body 로 이미지를 받는다.** multipart 는 임계값을 넘으면 서블릿
  컨테이너가 디스크에 임시 파일을 만든다. 디스크 경로 자체를 만들지 않는 편이 확실하다.
- **RAM 에서만 처리**하고 참조를 즉시 끊는다. 세션 객체에는 분석 결과 텍스트만 들어간다.
- **에러 로그에 base64 이미지가 찍히는 사고를 막는다** — 예외 메시지를 서버가 새로
  만들어 쓴다. 디코딩 실패 시 원본 문자열을 메시지에 넣지 않는다. *(가장 흔한 실수)*
- 액세스 로그·APM·CDN 캐시에 요청 바디 미포함.
- **영속 저장소를 두지 않는다.** 세션은 인메모리이며 무입력 타임아웃으로 폐기된다.
  파일 저장소·업로드 디렉터리·오브젝트 스토리지 어느 것도 구성하지 않는다.

> 저장하지 않는다는 주장은 **저장할 경로가 없을 때만** 검증 가능하다. 시연에서
> "코드에 저장 경로가 없음"을 보여주는 것이 문장 열 줄보다 강하다.

---

## 4. 수집하지 않는 것

- **얼굴 임베딩·생체 정보 일절 미수집** (수집 시 규제 등급이 완전히 달라진다)
- 개인 식별자·재방문 인식 없음 → **동일 인물 추적 불가능하도록 설계**
- 구매 이력·연락처 등 CRM 데이터 미연동
- **고객의 촬영 행위 미관측** — 확산을 정확히 세려면 고객 행동을 관측해야 하고,
  그 순간 프라이버시 우위가 사라진다. 측정을 포기하는 쪽을 택했다 (PRD §5.2)

---

## 5. 향후 개인화와의 관계

운영 단계에서 멤버십·구매 이력과 연계하면 개인화 수준을 높일 수 있다. 다만 그것은
**고객의 명시적 동의를 전제로 한 별도 기능**이며, 현재 설계의 "추적하지 않는다"와
충돌하지 않도록 처음부터 옵트인으로 분리해 두어야 한다.

익명 세션 경험과 식별된 개인화 경험을 같은 파이프라인에 섞으면, 나중에 어느 데이터가
어느 동의 아래 수집됐는지 되짚을 수 없게 된다.
