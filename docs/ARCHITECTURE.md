## 1. 시스템 구성

```
[미러 화면 — 고객용 (대형 디스플레이)]
  ├─ 카메라 (분석용 캡처 전용 — 단일 용도)
  ├─ 조명 렌더러 (CSS/Canvas + video filter·blend)
  ├─ 음원 재생 + 절차적 앰비언스 폴백
  └─ 상태 머신: 대기 → 동의 → 분석중 → 무드연출 → 분기선택
                → [응대대기 → 응대중] → 리셋
        │
        │  /api/mirror/**   ← 고객 경로. 추천 엔드포인트 없음
        ▼
[백엔드 API 서버]
  ├─ 세션 관리 (session_id, 상태 머신, 무입력 TTL)
  ├─ 1차: 이미지 수신 → Vision LLM (무드·조명·음악)  ※ RAM only, 미저장
  ├─ 2차: 무드 → 룰 프리필터 → GPT 랭킹 → 추천 3종/카테고리
  ├─ 3차: 후보 곡 → GPT 선곡
  ├─ 제품 ID 검증 (할루시네이션 차단)
  ├─ 직원 알림 발행
  └─ 폴백 프리셋 제공
        │                              │
        │ 조회                          │  /api/staff/**  ← 직원 경로
        ▼                              ▼
[제품 카탈로그]                 [직원 화면 — /staff (태블릿/모바일)]
  가방 15 / 지갑 15 / 벨트 14     ├─ 대기 목록 (대기 오래된 순)
  (§2 스키마)                     ├─ 응대 카드 (무드 · 팔레트 · 추천 3종)
                                  ├─ 응대 시작 / 중복 방지 잠금
                                  └─ 응대 설문 입력 (P1)
```

- **프론트**: 웹. 미러 화면은 대형 디스플레이용, 직원 화면은 모바일 우선의 **별도 라우트**.
- **백엔드**: 경량 API 서버 (LLM 프록시 + 음원 검색 + 세션/알림 브로커). **사진 스토어 없음.**
- **DB**: 제품 카탈로그는 정적 JSON 으로 충분. 세션은 인메모리 + 무입력 TTL. **영속 저장소 없음.**
- **LLM**: Vision 지원 모델 (Structured Outputs / JSON Schema 강제).

API 경로가 고객용과 직원용으로 갈라져 있는 이유와 그 장치는 [API_SPEC](API_SPEC.md) 참고.

## 2. 제품 카탈로그 데이터 모델

**3개 카테고리 44종** (가방 15 / 지갑 15 / 벨트 14).
제품명·가격·이미지·제품URL 은 MCM 공식 온라인 스토어의 실제 데이터를 사용하고,
추천 로직용 `styleTags` / `formality` / `storeLocation` 만 수기로 부여한다.

```json
{
  "id": "MCM-BAG-014",
  "category": "bag",
  "name": "Stark Backpack in Visetos",
  "line": "Visetos",
  "colors": ["cognac", "brown"],
  "material": "coated canvas",
  "price_krw": 1150000,
  "style_tags": ["street", "iconic", "casual", "unisex"],
  "formality": 0.3,
  "size": "medium",
  "image_url": "...",
  "product_url": "...",
  "store_location": "1F 백팩 존"
}
```

| 필드 | 용도 |
|---|---|
| `category` | `bag` \| `wallet` \| `belt` |
| `colors` | 착장 팔레트와의 조화도 계산 (톤인톤 / 포인트) |
| `style_tags` | 무드 태그와 교집합 점수 산출 |
| `formality` | 착장 포멀리티(0~1)와의 근접도 |
| `store_location` | **직원 응대 카드에 표시 — 픽업 동선 단축** |

- 데이터·이미지 출처는 MCM 공식 온라인 스토어. **해커톤 시연 한정 사용**임을 명시한다.
- 제품 이미지는 MCM 이미지 CDN 을 직접 참조한다 (별도 사본을 만들지 않는다).
- 재고 정보는 포함하지 않는다. 응대 카드에 "매장 재고 확인 필요"를 상시 표기.
- `storeLocation` 은 매장마다 달라 현재 값은 임시다. 파일럿 매장 확정 시 실측 레이아웃으로 교체.

> **제품 정보를 기계가 읽을 수 있는 형태로 구조화해 두는 것은 장기 자산이다.**
> 지금은 할루시네이션 방지 장치지만, 외부 AI 에이전트가 브랜드 정보를 해석하기
> 시작하면 브랜드가 자기 정보의 표현을 통제하는 수단이 된다 (PRD §2.4).

## 3. 추천 로직

### 3.1 파이프라인

```
1차 Vision 분석 결과 (mood, palette, style, formality)
        │
        ▼
[룰 기반 프리필터]  ─ 카테고리별 후보 6~8개 추출
   score = w1·(style_tags ∩ mood_tags 개수)
         + w2·(색상 조화도: 톤인톤 or 보색 포인트)
         + w3·(1 - |formality_item - formality_outfit|)
        │
        ▼
[GPT 랭킹 호출]  ─ 후보군 + 무드 컨텍스트
   → 카테고리별 3개 선정 + 순위 + 한 줄 추천 이유
        │
        ▼
[서버 검증]  ─ product_id 실존 여부 대조
   → 미존재 ID 폐기 → 프리필터 점수 상위로 자리 채움
        │
        ▼
[직원 화면으로만 전송]  ─ 고객 화면에는 전달하지 않음
```

가중치는 태그 .45 / 색상 .35 / 포멀리티 .20.

### 3.2 할루시네이션 차단 (필수)

이 기능의 유일한 치명적 리스크는 **존재하지 않는 MCM 제품을 그럴듯하게 생성**하는 것이다.
직원이 그 제품을 찾으러 가는 순간 서비스 신뢰가 무너진다. 3중으로 막는다.

1. **GPT 는 제품명을 생성하지 않는다.** `product_id` 만 선택하게 한다. 제품명·이미지·가격·위치는 전부 카탈로그에서 렌더링한다.
2. **JSON Schema 의 `enum` 에 유효한 후보 ID 를 열거**한다. Structured Outputs 사용 시 디코딩 단계에서 강제된다.
3. **서버에서 반환 ID 를 카탈로그와 재대조**한다. 미존재 시 폐기 후 프리필터 상위 항목으로 대체.

서버 검증은 세 가지를 본다 — 실존 여부, 선언한 카테고리와 실제 카테고리의 일치,
같은 제품의 중복.

> **중복 판정은 ID 가 아니라 표시 이름 기준이다.** 카탈로그에는 같은 제품이 색상별로
> 여러 SKU 로 들어 있어서 ID 로만 막으면 직원 카드 3칸 중 2칸이 같은 물건이 된다.
> 게다가 표기가 `"M-Art 비세토스 1인치 벨트"` / `"M-Art 비세토스 벨트 1인치"` 처럼
> 어순만 다른 경우가 있어, 공백으로 쪼개 정렬한 값을 키로 쓴다.

### 3.3 지연 시간 설계

2차 호출은 **조명·음악 연출이 시작되는 즉시 백그라운드로 실행**된다. 고객은 이미 연출을
보고 있고, 결과는 고객 화면이 아니라 직원 화면으로 가므로 **지연이 고객에게 전혀 노출되지
않는다.** 분기 선택 시점까지는 여유롭게 완료된다.

## 4. 비기능 요구사항

- **지연시간**: 촬영 → 조명 연출 시작 목표 6초 / 최대 8초. 추천 생성 → 직원 카드 도달 목표 3초 / 최대 5초. 초과 시 단계별 진행 표시로 체감 지연 완화.
- **실시간성**: 고객 요청 → 직원 화면 알림 도달 1초 이내 (목표). 현재는 폴링 기반이라 미달.
- **고객 주도권**: "혼자 볼게요"는 다른 선택지와 **동등한 시각적 비중**으로 배치한다. 숨기거나 작게 만들지 않는다 (PRD §3.4 전략 요소).
- **AI 출력 비공개**: 고객 화면 어디에도 제품명·추천 결과가 노출되지 않아야 한다. `style_comment` 프롬프트에 제품 언급 금지를 명시하고, 렌더링 단계에서도 필터링한다.
- **동시성**: 미러 여러 대가 동시에 붙는 것을 전제로 한다. 세션 저장소와 이벤트 로그 모두 동시 쓰기에 안전해야 한다.
- **안정성**: 네트워크·API 장애 시에도 데모가 죽지 않도록 전 구간 폴백.

## 5. 엣지 케이스 & 폴백

| 상황 | 대응 |
|---|---|
| LLM 1차 응답 실패/타임아웃 | 사전 정의 조명·음악 프리셋 5종 중 이미지 해시로 선택 + 기본 컨셉명 표시 |
| LLM 2차(추천) 응답 실패 | 프리필터 점수 상위 3종을 직원 카드에 표시. 추천 이유는 템플릿 문구 |
| GPT 가 존재하지 않는 product_id 반환 | 서버 검증에서 폐기 → 프리필터 상위로 자리 채움 (§3.2) |
| `style_comment` 에 제품명이 섞임 | 렌더링 전 카탈로그 제품명 매칭 필터로 차단, 해당 문장 미표시 |
| 여러 명 감지 | 가장 중앙·큰 인물 기준 분석 (프롬프트로 지시) |
| 저조도/역광으로 착장 인식 불가 | "조금 더 가까이 서주세요" 안내 후 재촬영, 2회 실패 시 폴백 프리셋 |
| **깨진 이미지 전송** | 400 반환. **세션은 `CONSENTED` 를 유지해 그대로 재촬영 가능** |
| 음원 검색 실패 / 후보 0곡 | 절차적 앰비언스로 폴백 (비트 포함 — [EXPERIENCE_SPEC](EXPERIENCE_SPEC.md)) |
| 브라우저 자동재생 차단 | 재생 버튼 노출. 사용자 제스처 후 재시도 |
| 카메라 권한 거부 | 안내 화면 표시, 데모 환경에서는 사전 권한 허용 |
| 고객이 응답 없이 이탈 | 무입력 타임아웃 시 세션 종료 + **미응대 알림 자동 취소** (직원 헛걸음 방지) |
| 직원이 전원 응대 중 | 대기 상태 표시. 알림은 목록에 유지 |
| 직원이 알림을 놓침 | 60초 초과 시 재알림 **(미구현 — 현재는 `waitingSeconds` 로 직원 화면이 판단)** |
| 중복 응대 | 한 직원이 "응대 시작"을 누르면 다른 단말은 409 `assist_conflict` |
| '혼자 볼게요' 세션에 직원이 접근 | 상태 전이 자체가 막혀 409 `illegal_state` |
| 추천 제품 재고 없음 | 재고 미연동이므로 카드에 "매장 재고 확인 필요" 상시 표기 |
| 다중 미러 동시 사용 | `sessionId` 로 분리, 직원 카드에 미러 위치 표시 |
